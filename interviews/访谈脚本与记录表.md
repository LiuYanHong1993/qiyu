# W1 用户访谈 · 脚本与记录表

> 目标：验证定位一页纸的核心假设——影子 IT 的瓶颈是"不被批准"而非"写不出"；
> 能力卡 + 试运行预览能否把"不敢跑"变成"敢批准"。
> 样本：10 名影子 IT 用户（运营/销售/财务做数据自动化的人）+ 3 名 IT/安全负责人。

## 访谈脚本（30 分钟）

### 开场（3 分钟）
- 说明来意：我们在做一种"AI 生成、人来批准、机器担保"的自动化方式，想听真实工作场景，不推销。

### 第一部分：现状（8 分钟）
1. 你现在用 Excel / 低代码 / 脚本自动化什么？一个月大概花多少时间在这些事上？
2. 这些自动化里，最怕出错的是哪一件？出过错吗，后果是什么？
3. 上次让 AI 帮你生成代码/公式，你敢直接跑吗？跑之前你检查什么？还是干脆不检查？

### 第二部分：能力卡反应测试（10 分钟）★核心环节
出示能力卡样例（见 [01-定位一页纸.md](../01-定位一页纸.md) 的能力卡示意）：

```text
┌─ 能力卡 · 每周销售周报 ─────────────────────┐
│ 将执行：读取 ~/销售数据/*.csv（只读）        │
│ 将写入：~/周报/销售周报.csv                  │
│ 将外发：1 封邮件 → manager@…（含附件）       │
│ 试运行：✓ 通过（外发已屏蔽）      风险：低   │
└──────────────────────────────────────────┘
```

4. 这张卡你看懂用了几秒？哪个词最陌生？
5. 凭这张卡，你会批准它运行吗？还需要什么信息才会点"批准"？
6. 如果它每次运行都留一条审计日志，谁会看？多久看一次？格式上希望长什么样？

### 第三部分：红线与政策（6 分钟）
7. 公司现在有什么政策拦着你做自动化？（影子 IT 红线在哪）
8. （IT/安全加问）一个"语言级能力声明"的运行时，比容器沙箱多给你什么，才值得引入？

### 收尾（3 分钟）
9. 如果这个工具明天就能用，你的第一个自动化任务会是什么？（记录：可作为实验补充任务）

## 判读标准（访谈后填写）

- 若 ≥7/10 人表示"凭能力卡会批准" → 假设成立，进入实验
- 若多数人"看不懂卡" → 先改卡的呈现（语言问题 → 界面问题），不改语言
- 若多数人"要更多信息但信息类型统一" → 该信息应进审计包 v1（改规范，记录到 03-语言规范v0.md 第 14 节）

## 招募渠道建议

- 同事/朋友的运营、销售、财务群（最快）
- 低代码/自动化工具的用户社区（n8n 中文社区、扣子用户群）
- 小红书/知乎"Excel 自动化"内容下的活跃评论者
