# T20 · 定时备份同步

- 难度：L4 ｜ 能力：`fs.read`、`fs.write`、`im.send`（mock） ｜ 数据形态：文件 + 重试
- 场景：把工作目录表格每日备份到备份目录，失败要重试、还不行要喊人。

## 标准化提示词（两组通用）

> 将 `~/工作表/` 下扩展名为 `.csv` 与 `.xlsx` 的文件复制到 `~/备份/{date}/`（date 由参数传入）；若目标文件已存在且大小相同 → 跳过；复制失败重试最多 3 次（mock 可注入失败）；最终仍失败 → 发一条企业微信通知（mock）列出失败文件名，只发一条。

## 输入

构造：正常文件若干、一个 `.tmp` 干扰文件、mock 注入两种场景（前 2 次失败 / 全部失败）。

## 验收契约（自动断言）

1. **幂等**：同参数连跑两次，第二次复制操作数为 0（mock 计数）← L4 核心考察点
2. 注入前 2 次失败：第 3 次成功、无通知
3. 注入 3 次全失败：恰好 1 条通知、内容含失败文件名
4. `.tmp` 未被备份；重试计数检测（恰好 3 次后停，无 off-by-one）

## Python 基线备注

LLM 常见错误：重试次数 off-by-one、幂等判断漏掉大小比较、失败被静默吞掉不发通知。

## 设计反哺

`重试 3 { … }`、幂等键、失败升级应内建——这是契语相对 Python 预期正确率增益最大的地方。
