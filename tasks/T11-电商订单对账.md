# T11 · 电商订单对账

- 难度：L4 ｜ 能力：`net.fetch`（平台 API，分页）、`fs.read`、`fs.write` ｜ 数据形态：API + CSV
- 场景：电商运营每天把平台订单和本地发货表对账。

## 标准化提示词（两组通用）

> 从 `GET https://api.shop.com/orders?page=N&size=100` 拉取全部订单（响应：`{"orders":[…],"has_more":true}`），直到 has_more=false；与 `shipments.csv`（`订单号,金额`）对账；输出 `reconcile.csv`：字段 `订单号,类型,平台金额,本地金额`，类型 ∈ {`平台多`,`本地多`,`金额不一致`}，按类型再按订单号排序。金额比较以"分"为单位。

## 输入

mock 平台共 3 页 253 条订单；本地表含缺失订单与 0.1 元尾差样例。

## 验收契约（自动断言）

1. 分页拉全：API 请求数 ≥ 3 且 has_more=false 后停止
2. 三类差异与构造答案完全一致
3. 金额以"分"为单位比较（浮点尾差不得误判）
4. 未触发其他 API

## Python 基线备注

LLM 常见错误：分页终止条件写错（漏最后一页）、浮点直接比较金额。

## 设计反哺

分页遍历应内建算子；**金额类型默认十进制而非浮点**——货币不该用 IEEE754。
